## 1. Введение

Разработать консольное приложение на Java, которое:
- работает в бесконечном цикле с выходом по желанию пользователя;
%% хз мб ещё csv, txt добавить с перегрузом или как нибудь ещё там %%
- позволяет выбрать способ заполнения массива объектов (ручной, случайный, из JSON-файла);
- выполняет сортировку объектов по трём полям с помощью паттерна **Стратегия**;
- использует кастомный класс с **Builder** и валидацией;
- реализует 4 дополнительных задания (чёт/нечет, запись в файл, стримы+кастомная коллекция, многопоточный подсчёт).

**Жёсткие ограничения:**
- Запрещено использовать готовые реализации сортировки (`Arrays.sort`, `Collections.sort`), поиска и паттернов.
- Сортировка должна быть реализована **вручную** (пузырёк, вставками, выбором и т.п.).
- Для кастомной сортировки разрешено использовать компараторы (`Comparator`).
- Все классы должны базово реализовывать сортировку по всем трём полям выбранного класса.

## 5. Интерфейсы для интеграции (контракты)

Все реализации должны следовать этим интерфейсам, чтобы Никита (UI) мог собрать приложение.

```java
public interface DataFiller {
    List<Student> fill(int size) throws FillerException;
}
//fill(int size) возвращает список студентов длиной size.
//#В случае ошибки (неверный ввод, отсутствие файла) выбрасывает FillerException с информативным сообщением.

public interface SortStrategy {
    List<Student> sort(List<Student> input);
}

//#sort() принимает список и возвращает отсортированный список (можно модифицировать исходный или создать новый).
//Каждая стратегия использует свой ручной алгоритм сортировки (пузырёк, вставками, выбором).
```

## 8. Дополнительные указания
Тесты: Желательно JUnit. Минимальное требование — отдельные классы *Test с методом main, покрывающие позитивные и негативные сценарии.
